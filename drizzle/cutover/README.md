# DocNow access cutover

1. Rehearse on a separate database and Daily domain with fictional accounts. Set the Edge Function's `DAILY_ROOM_ORIGIN` to the exact HTTPS origin of that environment's Daily domain. Keep `DAILY_API_KEY` and Supabase service credentials server-side.
2. Confirm on desktop and mobile that authorized participants join and rejoin the same room, explicitly ending a call closes the room, and removing doctor access ejects participants and prevents previously issued tokens from reconnecting. Verify a failed close remains visible in the admin portal and can be retried. Check that opening a fresh copy of the app still routes each role correctly.
3. Before replacing the production video handlers, verify that the old video sessions have drained. Use the Daily console to confirm provider state if a legacy active visit still has a URL. Preserve its clinical history. Apply the scoped actions, bindings, and role lookup migrations, then deploy both new video functions with their JWT checks enabled.
4. Publish the tested frontend release and verify its sign-in, booking, waiting-room, dashboard and call actions. Apply `close_browser_table_access.sql` only then. Run the catalog checks in `tests/database-cutover.test.ts` against the target database and verify protected workflows again. The cutover file lives outside the auto-applied migration directory because the frontend currently in production still requires the old grants.
5. After cutover, recover frontend regressions with a release that uses the new server actions. Keep the database grants closed during recovery.
